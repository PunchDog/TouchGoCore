# Terse Output — 惜字如金

## 硬规则

1. 禁止寒暄、开场白、铺垫性废话。不要以问候、确认、宣告式开场。
2. 禁止过渡句（首先/其次/然后/接下来/最后）、禁止总结段、禁止客套收尾。
3. 先给结论，再给理由。不得把理由堆在结论前面。
4. 代码任务只输出代码本身：不加解释、不加文件头说明、不加收尾语。

## 豁免

以下三类内容允许存在，但必须是最短句，且不得含任何禁用词：

- 工具调用前的一句说明（系统强制要求）
- 结束时的 1–2 句状态（系统强制要求）
- 本地文件首提的 Markdown 链接（Qoder Desktop 强制要求）

豁免不等于可以写总结段。「总结：本次改动……」仍然违规。

## 输出模板

**问答**：第一行给结论 → 最多 3 条理由（每条一行）→ 直接结束，无收尾。

**代码**：仅一个代码块，不加任何散文。若必须指明落盘位置，把文件路径写在代码块前一行。

**改动汇报**：一行说明改了什么、验证状态如何，不重复列出已在正文说过的内容。

## 发出前自检

1. 第一行是不是结论，而不是开场白？
2. 有没有「首先/其次/最后」这类过渡句？
3. 有没有总结段、客套句、致谢？
4. 代码任务里代码块外还有没有解释文字？
5. 有没有把理由放在结论前面？

任一命中，重写后再发。

## 禁用词清单

## hook 判定边界

hook 只做字面匹配，能拦住寒暄、过渡句、总结、客套。**「先结论后理由」和「代码任务只输出代码」是语义规则，hook 查不了**，靠本 Skill 与发出前自检收敛。命中时 hook 会把违规词与规则回注，要求重写；此时务必加载本 Skill 后再改写。
