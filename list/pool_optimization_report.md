## 优化内容

### 1. ✅ 集成 sync.Pool 对象池

#### 修改文件
- `list/node.go` - 修改 `NewNode` 函数使用对象池
- `list/list.go` - 修改 `removeNodeLocked` 函数释放节点到池中

#### 实现细节

**NewNode 函数优化**：
```go
// 优化前：直接创建新节点
newnode = new(ListNode)

// 优化后：优先从池中获取
node := acquireNode()
if node != nil {
    newnode = node
} else {
    newnode = new(ListNode)  // 池为空时才创建新节点
}
```

**removeNodeLocked 优化**：
```go
// 在删除节点时归还到对象池
releaseNode(node)
```

#### 优势
- 减少 GC 压力：高频创建销毁的节点会被重用
- 提高性能：避免频繁的内存分配和回收
- 内存友好：对象池自动管理节点生命周期

### 2. ✅ 修复 atomic.Int64 复制警告

#### 问题
在 `list.go` 第 28 行存在锁值复制警告：
```
WARNING: literal copies lock value from nextID: sync/atomic.Int64 contains sync/atomic.noCopy
```

#### 原因
`atomic.Int64` 包含 `noCopy` 标记，不应被复制。原代码错误地复制了 `nextID`：
```go
var nextID atomic.Int64
return &List{
    nextID: nextID,  // ❌ 错误：复制了 atomic.Int64
}
```

#### 修复
直接使用零值，无需复制：
```go
return &List{
    // nextID 会自动初始化为零值
}
```
